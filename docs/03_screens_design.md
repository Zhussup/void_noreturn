## 1. Общие правила

Всё, что делает игрок, происходит **на трёх физических экранах**. Никаких окон поверх
мира, никакого HUD, никакого курсора. Управление — только клавиатура (QTE-ввод команд,
стрелки/цифры/Enter — выбор и подтверждение).

### Физические параметры

| Экран | Физический размер | Дистанция | Aspect | Канвас для макета |
|---|---|---|---|---|
| Монитор 1 — GANDEX-OS «Терминал» (взлом) | 0.50 × 0.31 м | ~0.9 м | ≈ 1.61 | **1440 × 900** |
| Монитор 2 — «МОНИТОРИНГ» (логи, кибербезы) | 0.50 × 0.31 м | ~0.9 м | ≈ 1.61 | **1440 × 900** |
| Ноутбук — «ОКНО» (VOID) | 0.30 × 0.18 м | ~1.2 м | ≈ 1.67 | **1200 × 720** |

Камера: FOV 45°, монитор занимает ~40% высоты кадра. **Правило читаемости:** основной
текст ≥ 28 px на канвасе 1440×900, минимальный — 22 px. Проверка — только скриншотом
из Play Mode, не в редакторе макета.

### Эстетика

- Плоский «корпоративный» UI без скевоморфизма: панели, линии, моноширинные списки.
- Терминал выглядит как софт, написанный десять лет назад и не обновлявшийся.
- Никаких иконок-эмодзи и иллюстраций — только текст, линии, блоки.
- Лёгкий CRT-дефект: сканлайны (очень слабые), виньетка, свечение текста.
  Сильные эффекты — только в состояниях тревоги/VOID.

### Шрифты (OFL, приложить файлы)

| Назначение | Шрифт | Начертания |
|---|---|---|
| Терминал, «ОКНО», команды | JetBrains Mono / IBM Plex Mono | Regular, Medium, Bold |
| Мониторинг, системные подписи | IBM Plex Sans / Inter | Regular, Medium, SemiBold |

### Общие диегетические элементы

- **Статус-строка** (верх): время смены (00:00 → 07:00), имя оператора `BRICK.E`,
  состояние задач, состояние личности (`БРИК` / `VOID`).
- **Строка подсказок** (низ): только клавиши — `[↑↓] выбор   [ENTER] принять`.
  Это часть диегетики: «программа» сама показывает клавиши.
- **Часы смены** — на всех трёх экранах, формат `ЧЧ:ММ`, реальное время смены.
- **Телефон** — не экран, но события звонка связаны с UI (см. §5).

## 2. Монитор 1 — GANDEX-OS «Терминал» (взлом)

Основной рабочий экран: вход на серверы, коды сотрудников, QTE-команды, очистка логов.

### Палитра

| Роль | Hex |
|---|---|
| Фон | `#050A08` |
| Основной текст (фосфор) | `#7DFF9C` |
| Приглушённый текст | `#3E7C50` |
| Рамки/линии | `#1E4A2E` |
| Предупреждение (янтарь) | `#FFC24A` |
| Тревога (красный) | `#FF5C5C` |
| Глитч VOID | `#F2FFF5` |

### Каркас

```
┌──────────────────────────────────────────────────────────────┐
│ GANDEX-OS · ДИУ-2    00:47 · ЗАДАЧ 3/5 · СМЕНА 07:00 · БРИК  │  статус
├───────────────────────┬──────────────────────────────────────┤
│ СЕРВЕРЫ / ЗАДАЧИ      │  ЦЕЛЬ: SRV-014 «АРГУС-2»             │
│ ▸ SRV-014  АРГУС-2    │  Доступ: BRICK.E + 3 сотрудника      │
│   SRV-009  ЛОГИ       │  ────────────────────────────────    │
│   …                   │  QTE-ввод:                           │
│                       │  ВВЕДИ: devs --all                   │
│                       │  ▮                                   │
│                       │  [проверка кибербезов: 00:42]        │
├───────────────────────┴──────────────────────────────────────┤
│ [↑↓] цель   [ENTER] ввод   [ESC] назад   КД: ███████░░░ 68%  │
└──────────────────────────────────────────────────────────────┘
```

### Состояния (обязательные макеты)

| ID | Состояние | Что показать |
|---|---|---|
| T1 | **Логин / старт смены** | Логотип GANDEX, `ОПЕРАТОР: BRICK.E`, пароль, 00:00, старт смены |
| T2 | **Задачи ночи** | Список задач (3–5), дедлайн 07:00, прогресс; провал задачи — красный |
| T3 | **Сервер / цель** | Список серверов, доступ, требование кодов сотрудников |
| T4 | **Коды сотрудников** | Экран выдачи чужих кодов; команда `devs --all`; чужие профили |
| T5 | **Взлом в процессе (QTE)** | Строка «ВВЕДИ: <команда>», мигающий курсор, таймер QTE, прогресс |
| T6 | **Логи** | Лента логов; «чистые», «грязные», «подозрительные» записи; очистка |
| T7 | **Пазл / глубина** | Команды и пароли, найденные в сюжете; многопольный ввод |
| T8 | **Тревога кибербезов** | «ЛОГИ ПОДОЗРИТЕЛЬНЫ», обратный отсчёт до выхода на игрока, красный |
| T9 | **Опечатка (бессонница)** | Символ не принят: курсор не двигается, символ мигает красным 0.2–0.3 с; уровень 1–3 |
| T10 | **Тревога (затемнение)** | Края мира и экрана темнеют; текст сохраняет контраст (читаемость!) |
| T11 | **VOID** | После звонка: холодный белый текст, команды без ошибок, «исправить всё» |
| T12 | **Конец смены 07:00** | Успех / провал задач / смерть — итоговый экран |

### КД кибербезов (обязательный виджет)

- Всегда виден во время взлома (концепт: «КД кибербезов будет на экране игрока»).
- Формат: полоса/кольцо `КД: 68%` + текст `проверка логов через 00:42`.
- Цвет: >60% — зелёный; 30–60% — янтарь; <30% — красный, пульсация 1 Гц.
- При срабатывании проверки — резкий переход в состояние T8.
- КД не должен перекрывать строку QTE-ввода.

## 3. Монитор 2 — «МОНИТОРИНГ» (логи и кибербезы)

Второй экран — обстановка: задачи смены, живые логи, статус кибербезов, тревога.

### Палитра

| Роль | Hex |
|---|---|
| Фон | `#0C0F0C` |
| Текст | `#B9D1C2` |
| Акцент | `#8FA6FF` |
| Норма | `#59FF9E` |
| Предупреждение | `#FFC24A` |
| Тревога | `#FF5C5C` |

### Состояния

| ID | Состояние | Что показать |
|---|---|---|
| C1 | **Обзор смены** | Задачи, время, прогресс, краткий статус серверов |
| C2 | **Логи в реальном времени** | Лента записей: кто, когда, что; подозрительность помечена |
| C3 | **Кибербезы** | Карточки сотрудников безопасности: имя, статус, КД проверки |
| C4 | **Подозрение растёт** | Красные пометки, счётчик подозрительных записей |
| C5 | **Служебные сообщения** | Сообщения начальства/безопасности (если появятся в сюжете) |
| C6 | **VOID** | Телеграфный стиль, белый акцент, сообщения «от себя» |
| C7 | **Смена окончена** | 07:00, итог ночи |

### Заметки

- Выбор вкладок — стрелками; непрочитанное подсвечено.
- Строка «печатает…» — три точки, корпоративный ритм.
- Логи не обрезать: скролл стрелками, ключевые строки закреплены.
- Кибербезы визуально «строже»: прямые углы, холодный цвет, без скруглений.

## 4. Ноутбук — «ОКНО» (VOID)

Личный экран Брика: канал VOID, следы провалов, вход в глубину. Визуально **другой
мир**: тише, темнее, интимнее, чем корпоративные мониторы.

### Палитра

| Роль | Hex |
|---|---|
| Фон | `#030807` |
| Текст | `#4CE6CC` |
| Приглушённый | `#1E6B60` |
| Глитч VOID | `#FFFFFF` |
| Тревожная мысль | `#FF6B8A` |

### Состояния

| ID | Состояние | Что показать |
|---|---|---|
| L1 | **Выключен / блик** | Отражение комнаты, блик лампы; крышка закрыта/приоткрыта |
| L2 | **Канал VOID** | Пустой тёмный экран, строки появляются по одной, без отправителя |
| L3 | **Следы провалов** | Записи, которых игрок не делал: время, команды, «ты уже начал» |
| L4 | **Инструкция / пароли** | Текст, найденный в сюжете; читается как личная заметка |
| L5 | **Смена личности** | Переход Брик → VOID: экран вспыхивает белым, почерк меняется |
| L6 | **Конец смены** | Итог ночи на личном экране |

### Заметки

- Текст на ноутбуке крупнее относительно канваса: экран меньше и дальше.
- Никакой «хакерской» зелёной матрицы — сдержанность; VOID страшен не графикой.
- Набор игрока виден: курсор, задержки, опечатки-исправления.

## 5. Особые механики и их визуал

| Механика | Как выглядит |
|---|---|
| **QTE-ввод** | Строка `ВВЕДИ: <команда>`; курсор двигается только при верном символе; таймер полосой; провал — красная вспышка строки |
| **Опечатка бессонницы** | Верная клавиша «не считается»: курсор стоит, последний символ строки мигает красным 0.2–0.3 с, лёгкое дрожание строки; уровень 1–3 усиливается |
| **Тревога** | Мир темнеет от краёв к центру (виньетка), цвета уходят в синеву; UI сохраняет контраст, пока игрок может действовать |
| **Успокоительное** | Действие «принять» — без меню: подсветка блистера/стакана в мире; после — виньетка отступает |
| **КД кибербезов** | Полоса/кольцо с процентом и обратным отсчётом; пульс <30%; сработка → T8 |
| **Звонок телефона** | Пульсация базы телефона в мире; на экранах — короткая системная строка `ВХОДЯЩИЙ ЗВОНОК`; после снятия — переход в VOID (L5) |
| **Смена личности** | Белая вспышка, смена палитры/шрифтового веса, «печать без ошибок» |
| **Смерть** | Полное затемнение; последним гаснет экран терминала |

## 6. Формат сдачи макетов

- **Инструмент:** Figma (или PSD) со слоями; шрифты приложить файлами.
- Канвас ровно 1440×900 (мониторы) и 1200×720 (ноутбук), без мокапов.
- Безопасные поля: 24 px по краям; ничего важного в первых/последних 16 px (CRT-маска).
- Экспорт каждого состояния — имена из [03_assets_checklist.md](03_assets_checklist.md).
- Тексты на макетах — **плейсхолдеры**; финальный текст живёт в локализации.
- Для динамических состояний (глитч, прогресс, КД, опечатка) — отдельные кадры/слои
  + описание анимации текстом; программист реализует в RenderTexture.
- Тёмная тема обязательна; светлая не нужна.

## 7. Критерии приёмки экранов

- [ ] Каждый экран читаем на скриншоте из Play Mode с рабочей дистанции.
- [ ] Ни одного состояния, где игрок не понимает, что делать дальше (подсказки клавиш
      присутствуют и диегетичны).
- [ ] Никаких элементов, требующих мыши.
- [ ] КД кибербезов заметен мгновенно и не перекрывает QTE-строку.
- [ ] Опечатка читается за 0.2–0.3 с, не спутать с лагом.
- [ ] При затемнении от тревоги текст остаётся читаемым, пока игра не закончена.
- [ ] Палитры различимы: терминал — зелёный, мониторинг — серо-зелёный с акцентами,
      ноутбук — тёмный бирюзовый, VOID — белый.
- [ ] Глитч-слой не скрывает критичную информацию больше чем на 1 секунду.
- [ ] Все тексты выдерживают двуязычие (EN длиннее на ~30%).
- [ ] Экспорт по именам и форматам из чек-листа.
