4. «Подозрительность кибербезов» и «следы Брика» есть как поля, но ни на что не влияют
   между ночами.
5. Нужен «снимок начала ночи» для перезапуска после смерти (сейчас сбрасывается вся игра).

## 5. Размер текста на мониторах (разбор, исправление НЕ применено)

### Что видно
Текст терминала мелкий, занимает часть ширины; у мессенджера шрифт выглядит крупнее.

### Что на самом деле
Замеры в Play Mode (`ScreenSurface` через reflection, RenderTexture сохранены в
`game/Captures/audit/rt_*.png`):

| | Терминал | Мессенджер |
|---|---|---|
| Экран `Screen` (lossyScale) | 0.432 × 0.324 м | 0.432 × 0.324 м |
| characterSize | 0.000933 | 0.000933 |
| Сетка Cols × Rows | **56 × 16** | **56 × 16** |
| Ортокамера стенда | size 0.162, aspect 1.333 | то же |
| RT | 1024 × 768 | то же |

**В RenderTexture оба экрана одинаковые** — кегль и сетка совпадают. Разница
складывается из трёх причин:

1. **Сетка зависит не от экрана, а от двух множителей.** В `TextMetrics`
   `k = lossyScale.y / 0.24` (= 1.35), а ортокамера стенда тоже берёт размер от
   `lossyScale` — масштаб монитора **сокращается**, т.е. 1.35 на относительный
   размер текста не влияет. Остаются:
   `Cols ≈ 60 / (OsTextScale × UiScale)`.
   С `OsTextScale = 0.72`: UiScale 1.0 → **85** колонок, 1.2 (по умолчанию) → **71**,
   1.5 → **56** (у меня в PlayerPrefs стоит 1.5). Дизайн экранов (`03_screens_design.md`)
   рассчитан на **60 × 19**. Экраны ОС Жусупа рисуют строки фиксированной длины
   (логин ≤ 33 символа, шапка 48), поэтому при 71–85 колонках текст занимает
   ~40–70% ширины. Попытка «fix sizes» (`0.85 → 0.72`) делала текст только мельче.
2. **Перспектива станций.** Станции терминала, мессенджера и стола стоят в одной
   точке `(0, 1.25, −0.55)`; оба экрана на расстоянии 0.906 м. На станции терминала
   мессенджер оказывается у края кадра, а при широком Game view (2.33:1,
   горизонтальный FOV ≈ 88°) край растягивается — его буквы кажутся в ~1.5 раза
   крупнее. На станции мессенджера всё наоборот (`Captures/audit/01_station_terminal.png`
   и `05_station_messenger.png`).
3. **Отступы абсолютные.** `padX = 0.012`, `padY = 0.010` м не масштабируются с
   экраном (на ×1.35 поля стали относительно уже). Мелочь, но сетка «плывёт».

### Предлагаемое исправление (А: `ScreenSurface`; Ж: удалить `TextMetrics`)
Сетка задаётся **колонками и строками**, а не кеглем. Кегль выводится из ширины
экрана, поэтому не зависит ни от масштаба монитора, ни от экрана.

```csharp
// ScreenSurface — эталонная сетка при UiScale = 1.2 (значение по умолчанию):
// 60 × 19, как в 03_screens_design.md. При 1.0 будет 72 × 22, при 1.5 — 48 × 15.
public const float DesignCols = 72f;
public const float DesignRows = 22.8f;
const float PadXFrac = 0.0375f;   // 0.012 / 0.32 — прежние поля в долях экрана
const float PadYFrac = 0.0417f;   // 0.010 / 0.24

// в SetupOutput, после расчёта advanceEm:
padX = width * PadXFrac;
padY = height * PadYFrac;
baseCharacterSize = (width - 2f * padX) / (DesignCols * advanceEm * (FontSize / 10f));
baseLineHeight = (height - 2f * padY) / DesignRows;
characterSize = baseCharacterSize * appliedScale;
lineHeight = baseLineHeight * appliedScale;
```

- `Create(screen, font, characterSize, lineHeight)` — аргументы кегля игнорируются
  (оставить для совместимости, пометить `[Obsolete]`), чтобы не трогать `NightDirector`
  сразу. Потом Жусуп удаляет `TextMetrics`, `OsTextScale`, `RefCharSize…`.
- Итог: оба экрана — одинаковая сетка, ровно 60 колонок при настройке по умолчанию,
  шапка ОС (48 символов) влезает даже при 1.5.
- Пункт 2 (перспектива) кодом `ScreenSurface` не лечится: нужно развести точки
  станций — `Station_Terminal` чуть перед терминалом, `Station_Messenger` перед
  мессенджером (позиции станций создаёт `VoidSceneBuilder` — зона Ж; якоря `Cam_*` —
  могу выставить я).

**Не применено — жду команды.**

## 6. Мониторы ×1.35: пересечения и кабели

Проверка — выпуклые оболочки мешей + `Physics.ComputePenetration` в Play Mode
(временные коллайдеры, в сцену не сохранены). Скриншоты — `game/Captures/audit/`.

| Пара | Результат | Комментарий |
|---|---|---|
| Терминал ↔ настольная лампа | **касание ~9 мм** | плафон/тяга лампы упирается в бок корпуса (`03_back_side_terminal_lamp.png`). Лампу сдвинуть на +3…4 см по X или развернуть |
| Терминал / мессенджер ↔ клавиатура | ~6 мм по оболочке | передняя кромка подставки над задним краем клавиатуры; по картинке не видно, но клавиатуру можно сдвинуть на 1 см к игроку |
| Терминал ↔ телефон | ок | зазор есть |
| Мессенджер ↔ ноутбук | ок | ноутбук частично под корпусом по AABB, по мешу нет |
| Мониторы ↔ окно, стена, батарея | ок | задняя стенка в 8 мм от рамы окна; мониторы закрывают низ окна — видна полоса ~25 см неба над ними |
| Мониторы между собой | ок | передние углы почти сходятся (`02_desk_top.png`) |

**Кабели (`SM_Cables`).** Генератор `ModelCables` строит точки выхода из задней
панели в координатах монитора ×1.0 (z = −0.16…−0.25 м). У монитора ×1.35 задняя
панель на z ≈ −0.26 м, поэтому дуга кабеля из разъёма **оказалась внутри корпуса**:
422 вершины кабеля внутри оболочки терминала, 144 — мессенджера. Снаружи кабель
появляется прямо из-под корпуса у столешницы, а не из задней панели. Шнур мыши
уходит под подставку на 5 см глубже — не видно, допустимо.
**Исправление (А):** в `ModelCables` учесть масштаб монитора (умножить локальные
точки на `MonitorScale = 1.35` или брать `lossyScale` из сцены) и пересобрать
меню «Партия 2». Сцену не трогал.
